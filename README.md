# WiFiProgrammer (کتابخانه گیرنده برای ESP32)

با این کتابخانه، یک ESP32 دیگر (فرستنده، مثلاً ESP32‑S3) می‌تواند برنامه این برد را **از طریق WiFi** عوض کند.
استفاده از آن فقط **یک خط** کد می‌خواهد.

```cpp
#include <WiFiProgrammer.h>

void setup() {
  WiFiProgrammer.begin();      // تنها خط لازم
}

void loop() {
  // کد شما (استفاده از delay() آزاد است)
}
```

کتابخانه در پس‌زمینه کار می‌کند. پس لازم نیست چیزی در `loop()` صدا بزنید و `delay()` هم مشکلی ایجاد نمی‌کند.

---

## نصب

۱. پوشه `WiFiProgrammer` را کامل در این مسیر کپی کنید:

- ویندوز: `Documents\Arduino\libraries\`
- مک و لینوکس: `~/Arduino/libraries/`

۲. یا پوشه را ZIP کنید و در Arduino IDE از `Sketch → Include Library → Add .ZIP Library` اضافه کنید.

۳. Arduino IDE را ببندید و دوباره باز کنید.

۴. بسته `esp32 by Espressif Systems` باید نصب باشد. برد باید ESP32 معمولی باشد و Partition Scheme پیش‌فرض (دارای OTA) داشته باشد.

مثال‌ها در منوی `File → Examples → WiFiProgrammer` هستند:

| مثال | برای کدام برد؟ | توضیح |
|---|---|---|
| `Basic` | گیرنده | ساده‌ترین مثال، فقط یک خط |
| `CustomSettings` | گیرنده | نام WiFi، رمز و کلید دلخواه |
| `Callbacks` | گیرنده | LED وضعیت و تابع‌های رویداد |
| `ManualMode` | گیرنده | حالت دستی با `handle()` |
| **`Sender_ESP32S3`** | **فرستنده** | **برنامه کامل فرستنده (ESP32‑S3) با LED رنگی و صفحه وب** |

> ✅ **یک نکته مهم:** این کتابخانه مخصوص **گیرنده** است. مثال `Sender_ESP32S3` برای **فرستنده** است و کتابخانه‌ای از آن استفاده نمی‌کند. فقط کد مستقل و آماده است. به این ترتیب کاربر با نصب یک کتابخانه هر دو برد را دارد.

## ساخت فرستنده (ESP32‑S3)

۱. از منوی `File → Examples → WiFiProgrammer → Sender_ESP32S3` مثال را باز کنید.

۲. تنظیمات برد را اینطور بگذارید:

- Board: `ESP32S3 Dev Module`
- USB CDC On Boot: `Enabled`
- Partition Scheme: یکی از حالت‌های دارای SPIFFS، مثل `Default 4MB with spiffs`

۳. در بالای کد، سه مقدار `RX_SSID`، `RX_PASS` و `OTA_KEY` را با مقدارهای گیرنده یکی کنید. اگر در گیرنده `WiFiProgrammer.begin()` را بدون ورودی نوشته‌اید، چیزی را تغییر ندهید.

۴. با USB آپلود کنید. LED فرستنده اول **قرمز** است و بعد از اتصال به گیرنده **آبی** می‌شود.

۵. به WiFi با نام `ESP32-Programmer` وصل شوید و رمزش `12345678` است. آدرس `http://192.168.5.1` را باز کنید و فایل bin را آپلود کنید. دکمه «پروگرام» یا دکمه BOOT روی برد، برنامه را به گیرنده می‌فرستد.

> اگر LED فرستنده روشن نشد، در بالای کد `LED_PIN` را تغییر دهید. در بردهای DevKitC نسخه 1.0 عدد 48 و در نسخه 1.1 عدد 38 است.

## راه‌اندازی در ۴ مرحله

| مرحله | کار |
|---|---|
| ۱ | مثال `Basic` را با **USB** روی گیرنده آپلود کنید (فقط همین یک بار). |
| ۲ | کد فرستنده (`Sender_S3.ino`) را روی ESP32‑S3 آپلود کنید. LED آن بعد از اتصال به گیرنده **آبی** می‌شود. |
| ۳ | برنامه جدید خود را بنویسید و حتماً `WiFiProgrammer.begin();` را در آن بگذارید. بعد `Sketch → Export Compiled Binary` را بزنید. فایل `نام‌برنامه.ino.bin` ساخته می‌شود. |
| ۴ | به WiFi با نام `ESP32-Programmer` وصل شوید و رمزش `12345678` است. آدرس `http://192.168.5.1` را باز کنید. فایل bin را آپلود و دکمه «پروگرام» را بزنید. |

رنگ LED فرستنده: قرمز یعنی گیرنده وصل نیست. آبی یعنی وصل است. نارنجی یعنی در حال پروگرام است. سبز یعنی تمام شد، و بعد از ۵ ثانیه دوباره وضعیت اتصال چک می‌شود.

> ⚠️ **مهم:** اگر برنامه جدید `WiFiProgrammer.begin();` نداشته باشد، بعد از پروگرام دیگر نمی‌توانید با WiFi آن را عوض کنید. در این حالت فقط USB کمک می‌کند. فایل bin را آپلود نکنید مگر مطمئن باشید این خط داخلش هست.

## توابع کتابخانه

### توابع اصلی

| تابع | توضیح |
|---|---|
| `WiFiProgrammer.begin()` | شروع با تنظیمات پیش‌فرض |
| `WiFiProgrammer.begin(ssid, pass, key)` | شروع با نام WiFi، رمز (حداقل ۸ حرف) و کلید دلخواه |
| `WiFiProgrammer.begin(ssid, pass, key, false)` | حالت دستی. باید `handle()` را در `loop()` صدا بزنید. |
| `WiFiProgrammer.handle()` | فقط در حالت دستی لازم است |
| `WiFiProgrammer.stop()` | متوقف کردن و خاموش کردن WiFi |

### توابع اختیاری

| تابع | توضیح |
|---|---|
| `setStatusLed(pin)` | LED مشخص‌شده هنگام پروگرام سریع چشمک می‌زند |
| `onStart(fn)` | وقتی پروگرام شروع شد |
| `onProgress(fn)` | با تغییر درصد پیشرفت، `fn(uint8_t percent)` صدا زده می‌شود |
| `onSuccess(fn)` | وقتی با موفقیت تمام شد. بعد از آن برد ریست می‌شود. |
| `onError(fn)` | هنگام خطا، `fn(const char* reason)` صدا زده می‌شود |
| `setDebug(false)` | خاموش کردن پیام‌های Serial |
| `isUpdating()` | آیا در حال پروگرام است؟ |
| `progress()` | درصد پیشرفت از ۰ تا ۱۰۰ |
| `lastError()` | متن آخرین خطا |
| `ip()` و `ssid()` | آدرس و نام WiFi گیرنده |

## تنظیمات پیش‌فرض (باید با فرستنده یکی باشد)

| مورد | مقدار پیش‌فرض |
|---|---|
| نام WiFi | `ESP32-Receiver` |
| رمز WiFi | `12345678` |
| کلید | `myKey123` |
| آدرس IP | `192.168.4.1` |

اگر `begin("نام", "رمز", "کلید")` را تغییر دادید، همان مقادیر را در کد فرستنده (`RX_SSID`، `RX_PASS`، `OTA_KEY`) هم بگذارید.

---

## نکته‌ها و عیب‌یابی

- **همیشه قرمز بودن LED فرستنده:** گیرنده روشن نیست، یا نام یا رمز WiFi با فرستنده یکی نیست.
- **خطای کلید:** کلید (`key`) در فرستنده و گیرنده یکی نیست.
- **خطای "not a valid ESP32 .bin":** فایل اشتباه آپلود شده است. فقط فایل `*.ino.bin` درست است، نه `bootloader.bin` یا `partitions.bin`.
- **خطای "no OTA partition":** در برنامه گیرنده، Partition Scheme را روی `Default 4MB with spiffs` یا هر حالتی که OTA دارد بگذارید.
- **استفاده از WiFi خودتان (STA):** کتابخانه فقط حالت Access Point را به حالت فعلی WiFi اضافه می‌کند. اگر WiFi خودتان را قبل از `begin()` روشن کنید، با آن سازگار است. بعد از `begin()` مستقیم `WiFi.mode(WIFI_STA)` را صدا نزنید، چون Access Point خاموش می‌شود.
- **پایه‌های GPIO:** هر کدام از پایه‌ها را که خودتان استفاده می‌کنید به کتابخانه ندهید، مگر اینکه برای `setStatusLed` باشد.

---

## چطور کار می‌کند؟

کتابخانه یک Access Point می‌سازد و یک سرور وب کوچک دارد:

- `GET /ping` جواب `PONG` می‌دهد. فرستنده با آن زنده بودن گیرنده را چک می‌کند.
- `POST /update` فایل bin را با هدر `X-Auth-Key` می‌گیرد و در فلش می‌نویسد.
- `GET /` یک صفحه اطلاعات ساده نشان می‌دهد.

بعد از موفقیت، پاسخ `UPDATE_OK` می‌رود و برد ریست می‌شود.
